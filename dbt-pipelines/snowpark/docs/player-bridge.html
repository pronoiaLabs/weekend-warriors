Why a procedure, not a model

Tiers, a batch Cortex Search job, and per-pair AI_FILTER are not a SELECT. dbt owns the address (the pre_hook passes this.database / this.schema); the procedure owns the content.

Why it reads RAW

No ordering dependency on the dbt DAG. A first-ever dest build still works. Every environment sees the same prod players.

The cheap path is the point If nothing is pending, the procedure returns a JSON summary and does not start a search job or spend an AI token. That is why dbt can call it on every build.

Two verdicts per pair

A candidate counts only when both say yes. The model alone accepted same-surname strangers (Rashod Owens → Tinker Owens). A naive prefix-only gate then blocked 91 true matches (Mike/Michael, De Cambra/Decambra, Dru/Andru).

AI_SAME · the model

AI_FILTER(PROMPT(A_TEXT, B_TEXT)). Surname must match; first name may be a nickname; team and jersey may be stale; college and birth year are strong when both present.

NAME_OK · the rules

First names: equal, prefix (min 2), contained (min 3), or a known nickname pair. A bare initial is not evidence. Surnames: rest after the first token, spaces stripped; equal or prefix with the shorter side ≥ 4.

How the dbt view keeps grain

The procedure maps many vendor rows → one gsis_id when the vendor really did import the same person twice (Vinny Testaverde, Chuck Wiley on BDL). The view ranks claims per vendor × gsis_id: strongest method, then lowest vendor id. The leftover claims are a warn-severity test — a jump there means the AI started saying yes to strangers again.

Deterministic-only floor, measured before search/AI existed: ~78% BDL · ~79% Sleeper. Test floor is 75%. Search + AI exist to eat the remainder without inventing matches.

What this design gets right

ChoiceWhy it is the right shape
Decide once, store ids onlyA crosswalk is identity, not a roster snapshot. Trades are a non-event.
Pending gate before CortexMakes a pre_hook on every dbt build free. The expensive path is the exception.
Ambiguity falls throughTwo John Smiths at exact do not coin-flip. Search + AI see every candidate and can reject all.
Search audits, never overridesDeterministic uniqueness stays authoritative. SEARCH_AGREES is a drift alarm.
Two-gate confirmEach gate exists because the other failed in measurement, not in theory.
Evidence-hash retryUnmatched players are not re-prompted forever. A real data change is the only retry.
Read RAW, write to the targetNo DAG coupling. Dev and prod share the index. Caller's rights write locally.
Temp-table cache, not cache_resultA CLI CALL may have no current database. Frames used twice must not rerun search or AI.

Cost shape

Steady state · every dbt build

pending = 0 → return. No search job. No AI_FILTER. This is the normal Sunday.

Full refresh or a new dump of players

One CORTEX_SEARCH_BATCH job over every pending row, plus one short AI_FILTER per residual × hit (up to 5).

If you only remember four rules

1

nflverse gsis_id is the spine. Everyone else maps onto it.

2

Exactly one candidate decides. Two candidates decide nothing.

3

Search is an auditor on the easy rows and a candidate source on the hard ones.

4

A miss is cheap forever, until the evidence itself changes.
