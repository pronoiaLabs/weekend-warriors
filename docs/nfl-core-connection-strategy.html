Every BallDontLie row keeps its seat at the head of the table, and nflverse and Sleeper pull up chairs beside it: usage shares, EPA, snap counts, fantasy scoring, live status, and play-level analytics grafted onto the paid spine through the two bridges already built for the job.

§ 1

The Strategy in One Screen

five principles, four phases

BDL anchors, always

BallDontLie is the paid source. It sits on the left side of every join; nflverse and Sleeper enrich the row, never replace it. Enrichment columns go NULL where a bridge has no match — a fact the row admits with has_nflverse / has_sleeper flags.

Wide facts, familiar shape

Player and team game facts stay offense / defense based, exactly as today. Each rebuilds as a wide table: BDL box score + nflverse analytics + Sleeper fantasy, one row per player-game or team-game.

Bridges are the spine

bridge_player_ids and bridge_game_ids stay the single identity authority. Dims carry denormalized convenience copies of the vendor ids; facts do the vendor joins once, centrally, so no consumer ever re-implements them.

CORE becomes cold storage

At cutover, CORE stops being a dbt target and its tables freeze at last-run state — an instant rollback archive for two release cycles, then dropped on an explicit date so it can't linger as a stale shadow.

Provenance over blending

Where both vendors report the same stat, both columns survive with vendor prefixes — the project already does this for defensive_touchdowns, which the vendors disagree on across 155 rows. Disagreement stays visible, never averaged away.

Why this is cheap to do Every downstream consumer — 8 semantic views, 20 APP marts, 4 feature marts, the singular tests — resolves through ref(), so the schema move itself requires zero model SQL changes. The blast radius is a dbt_project.yml config split plus five hardcoded CORE references. And the game facts are small (≈23k player-games, ≈2k team-games): full rebuilds cost pennies, which frees the wide facts from the incremental machinery entirely.

Connection Map

three id universes, two bridges, one spine

Every join in the enriched layer reduces to this picture. BDL surrogate keys are the conformed spine; nflverse and Sleeper reach it only through the bridges, and each wide fact does that traversal exactly once.

Blue paths are the primary traversals every wide fact performs. The team-abbreviation macro is the third vocabulary that must move in lockstep with the Snowpark evidence maps and the Cortex Search filter attribute.

The 1:1 key collisions (all deliberate)

  • team_game_key: fact_team_game_offense = fact_team_game_defense — and, until absorbed, fact_team_game_epa. The wide rebuild folds the third into the first two.
  • player_game_key: shared key space across the three player phase facts — 4,604 player-games appear in more than one phase. Row counts never sum; never UNION them. This stays true after the rebuild.
  • player_game_key on fact_two_point_conversion matches the phase facts by construction.
Week-grain → game-grain is safe in the NFL nflverse player stats and Sleeper stats live at player × season × week, not player × game. Because an NFL team plays at most one game per week, (gsis_id, season, week) → team that week → game_key resolves deterministically through bridge_game_ids. The wide facts do this once; an unmapped-rows audit catches the residue (mid-week trades, postseason vocabulary) instead of silently dropping it.

Enrichment Plan

what each table gains, and from where

BDL row on the left, enrichment blocks joined in. Vendor prefixes where both sides report the same stat; has_nflverse / has_sleeper flags so a NULL reads as "no match," never "zero."

Dimensions

dim_player the big one

via bridge_player_ids → stg_nfl__nflverse_players + stg_nfl__sleeper_players

  • Bio & draft — birth_date, draft_year / round / pick / team, college_conference, rookie_season, years_of_experience, headshot_url, high_school (Sleeper)
  • Position repair — coalesce(bdl ≠ 'Unknown', nflverse, sleeper) + a provenance column; fixes 8,379 of 13,503 Unknown rows and back-fills the 9,715 missing height/weight
  • Denormalized ids — gsis, sleeper, espn, pfr, sportradar, yahoo, rotowire (bridge stays authoritative)
  • Live status — injury_status, injury_body_part, practice_participation, depth_chart_position / order, search_rank (Sleeper daily; history stays on fact_injury_report / fact_depth_chart)
  • Flags — has_nflverse_match, has_sleeper_match

dim_team & dim_game

via bridge_game_ids + nflverse teams/officials reference

  • dim_team — nflverse_abbr (ends re-deriving it per query), colors / logos, stadium_key FK
  • dim_game — nflverse_game_id denormalized, referee (head official), is_division_game
  • fact_team_season — bye_week (team × season attribute; derivable from dim_game gaps)
  • Full officiating crew is a fact, not dim columns → fact_game_official

Wide facts

fact_player_game_offense

BDL box score (anchor) ⟵ nflverse player week + snap counts + Sleeper stats

  • BDL block (unchanged) — passing / rushing / receiving box, scrimmage rollups, fanduel_points, draftkings_points (UDFs kept)
  • Usage — target_share, air_yards_share, wopr, racr, pacr, air yards, YAC, first downs, explosive-play buckets
  • Efficiency — passing/rushing/receiving EPA, passing CPOE
  • Snaps — offense_snaps / offense_pct (nflverse, pfr crosswalk) + sleeper_off_snap_share (team-denominator cross-check)
  • Fantasy — sleeper pts_std / half_ppr / ppr + position ranks; nflverse fantasy_points as the second opinion
  • Optional (decide in build) — headline NGS per discipline (CPOE-above-expected, RYOE, avg_separation); full NGS depth stays on fact_nextgen_*

fact_player_game_defense & _special

BDL (anchor) ⟵ nflverse def_* / kicking blocks + Sleeper IDP

  • Defense — nflverse def_* block (≈20 cols: pressures-adjacent counting stats), Sleeper IDP (idp_tkl, idp_sack, idp_int, idp_ff, idp_qb_hit) beside BDL tackling / pass rush / coverage; defense_snaps / defense_pct
  • Special — FG made/attempted by distance band (0-19 … 60+), game-winning FG, punting detail, return detail; st_snaps / st_pct

fact_team_game_offense & _defense

  • Offense twin — absorbs off_epa, epa_per_play, success_rate, early_down_success_rate, pass/rush EPA splits, explosive_rate, pass_rate, PROE
  • Defense twin — absorbs def_epa, success_rate_allowed, dropbacks_faced, pass/rush EPA allowed, explosive_rate_allowed
  • Rates never materialized as averages of averages — recomputed from this grain's own sums, as today
Coverage is partial by construction — and that's fine Name + team matches about 78% of current nflverse players to BDL; the bridge's id and Cortex Search tiers push higher, but some rows will always carry NULL enrichment. The flags make coverage measurable per column, and the retired vendor-pure facts remain in cold storage (and RAW) if a gsis-only view of the world is ever needed again.

Cold storage, operationally

  • What it is: at cutover CORE simply stops being a dbt target. dbt drops nothing — the tables freeze at last-run state automatically.
  • What it's for: instant rollback (revert the +schema values and two macro literals) and the archive of the retired vendor-pure facts.
  • When it dies: after two prod release cycles, drop the schema on an explicit date. A frozen schema without a death date becomes a stale shadow copy someone will eventually query by accident.
  • Grants: DIM and FACTS need creating + ownership transfer to DBT_RUNNER_ROLE in the provisioning SQL. Consumers are untouched — the dashboard reads APP (copy_grants intact), the agent reads ANALYTICS.

Play-by-Play: Finding the Happy Place

two vendors, one spine, a prop-pattern engine

BDL's fact_play and nflverse's raw pbp describe the same plays with different superpowers. The happy place: BDL stays the spine (its play_key already connects to everything), nflverse becomes both the per-play analytics graft and the coverage backstop — and the situational aggregates that actually drive prop decisions don't depend on row-perfect matching at all.

The two sources, honestly compared

BDL fact_playnflverse_pbp (RAW)
Coverage179,402 plays — but 18 games have no plays at all (never use as a game spine)Every game, every play, back through the backfill floor — covers the 18 gaps
Keysplay_key, game_key, team_key (nullable on 126 neutral plays), play_type_keynflverse_game_id + play_id; gsis player ids on every role (passer, rusher, receiver, tacklers…)
Situationperiod, clock, down, distance, yard line, red zone / third / fourth down flagssame, plus drive/series context, shotgun, no-huddle, personnel-adjacent fields
Analyticsyards gained, scoring flags, home win probabilityEPA, WPA, success, CPOE, air yards, xpass and ≈360 more columns
Today's usagefull model, clustered by season/weekread directly from RAW by exactly two models — a huge untapped surface

Prong 1 — play-level graft onto fact_play

  • Scope to a game first via bridge_game_ids, then match within it in tiers: T1 quarter + game clock + down + distance + yardline (deterministic for the vast majority); T2 relax the clock a few seconds for entry drift; T3 normalized description similarity as the last resort.
  • Graft where matched (BDL left, nflverse enrich): epa, wpa, success, air_yards, yards_after_catch, xpass, pass/rush metadata, and the nflverse play_id for drill-through.
  • Audit, don't assume: a match-rate model per game with a test threshold. Unmatched BDL plays keep NULL analytics; nflverse-only plays (including the 18 missing games) are surfaced by the audit rather than invented into the BDL spine.

Prong 2 — situational splits: the pattern surface for props

Built from the new curated stg_nfl__nflverse_pbp prep regardless of match rate. New fact fact_team_game_situation, grain team × game × situation, both sides of the ball:

Situation dimensions

  • down (1st / 2nd / 3rd-4th) × distance bucket (short / medium / long)
  • field zone (own territory / midfield / red zone)
  • play family (dropback / designed run), shotgun, no-huddle
  • game state (leading / trailing / neutral script, two-minute)

Measures per cell

  • plays, EPA/play, success rate, explosive rate
  • pass rate and pass rate over expected (PROE)
  • yards/play, first-down rate
  • the defense mirror: everything as "allowed"
Why this wins prop bets app_team_allowed already answers "what does this defense give up by position." Situational splits answer the sharper question: "this defense collapses on third-and-long dropbacks" or "this offense abandons the run when trailing." Cross that with the wide player fact's target share and snap share, the Sleeper projection line, and the book's prop line — all now joined on the same keys — and the prop board can show line vs projection vs situational matchup in one query. Season-to-date and rolling windows aggregate downstream in FEATURES/APP from the game grain, so the fact stays additive.

Migration Phases

Phase 0 ships alone; each phase is dev-built, then deploy-sport
Phase 0 Schema cutover — deliberately SQL-inert no model SQL changes; the rollback is two files
  • Provision: add DIM + FACTS to dlt-pipelines/sql/sources/nfl/01_databases.sql (CREATE SCHEMA list) and 05_dbt_trigger.sql (ownership transfer to DBT_RUNNER_ROLE); template the same in tools/new_source.py. Run against prod as the usual human-run make setup-* path.
  • Config: in dbt_project.yml, split core: +schema: CORE into dimensions: +schema: DIM, bridges: +schema: DIM, facts: +schema: FACTS. Folder names don't change — config keys mirror directories, so only the values move.
  • Macros: nfl_player_bridge_fqn() → 'DIM'; nfl_fantasy_points_fqn() → 'FACTS'.
  • Cortex Search: recreate PLAYER_SEARCH in DIM (09_player_bridge.sql), update the snowpark package's hardcoded FQN, make deploy-snowpark — before the first prod run.
  • Pre-clone the three incremental facts (CREATE TABLE …FACTS.X CLONE …CORE.X for player offense / defense / special) so the first prod run stays incremental instead of a cold rebuild. Moot once Phase 2 retires the incremental spine, but Phase 0 ships first.
  • Ship: dev dbt build (models + tests), then make deploy-sport SPORT=nfl. All semantic views, APP and FEATURES rebuild against the new schemas via ref() untouched.
  • After: repoint the ML specs FQN to FACTS. Freeze CORE; write down its drop date.
Phase 1 Dimension enrichment dim_player · dim_team · dim_game
  • Rebuild dim_player wide: bio/draft block, position repair with provenance, denormalized ids, Sleeper live status, match flags. Bridge ordering is already correct (dim builds after bridge_player_ids).
  • dim_team: nflverse_abbr, colors/logos, stadium_key. dim_game: nflverse_game_id, referee, is_division_game — needs a thin stg_nfl__nflverse_officials prep model.
  • Tests: position_source distribution, id uniqueness where present, match-rate thresholds alongside the existing bridge tests.
Phase 2 Wide fact rebuilds the five game facts + new small facts
  • Rebuild the five team/player game facts wide (BDL-anchored, enrichment blocks per § 4). Retire the incremental spine — plain tables at this scale.
  • Absorb fact_team_game_epa into the team twins; retire fact_nflverse_player_week, fact_player_week_snaps, fact_sleeper_player_week, and the six BDL advanced facts to cold storage as their columns land.
  • New: fact_game_official, fact_player_combine, bye_week on fact_team_season; fact_trade when it earns its slot.
  • Tests: player_game_key / team_game_key uniqueness, unmapped-week audit, vendor-disagreement spot checks (the defensive_touchdowns pattern).
Phase 3 Play-by-play graft + situational splits
  • stg_nfl__nflverse_pbp curated prep (ends the two direct RAW reads; fact_team_game_situation and the team twins' EPA blocks read it).
  • Play-level match (tiers T1–T3) + graft onto fact_play; per-game match-rate audit model with a warning threshold.
  • fact_team_game_situation per § 6.
Phase 4 Semantic views + APP expose the riches
  • sv_nfl_player_offense: usage / EPA / fantasy measures now ride the wide fact with full coverage — the disabled sv_nfl_player_advanced (dead for disjoint-coverage reasons) becomes permanently unnecessary.
  • sv_nfl_team_performance: EPA, success rate, PROE measures. New semantic view on situational splits for "what does this defense allow on third and long" questions in plain English.
  • APP: app_player_weeks / app_player_leaders + usage columns; app_game_prop_board + projection-vs-line delta + situational matchup columns; app_game_slate + referee and injury-status rollup; explore sheets pick up the new columns as their contracts allow.
  • Agent instructions and AI_VERIFIED_QUERIES refreshed where measures were added.

§ 9

Risks & Gotchas

named now, cheap later

Dev can't rehearse the split

Collapsed dev schemas mean DIM/FACTS, the macro FQNs and the search-service move are first exercised in prod. Mitigation: Phase 0 is SQL-inert, and frozen CORE is the instant rollback.

Externals ordering at cutover

PLAYER_SEARCH must be recreated before the first prod run; the ML FQN repoints after. In between, ML reads frozen CORE — stale for a beat, never broken.

Vendor disagreement moves indoors

Wide facts put both vendors' numbers on one row. Policy: prefixes + flags, disagreements documented in the models yml, never silently coalesced for measures (coalesce is for dims like position, with provenance).

Week→game edge cases

Postseason vocabulary is solved in the bridge; mid-week team changes are not. Uniqueness tests on the wide fact keys + an unmapped-rows audit catch what the join can't decide.

Play-match rate < 100%

Unmatched plays keep NULL EPA — never imputed. The per-game audit makes the rate a monitored number instead of a hope, and situational splits don't depend on it at all.

NGS is discipline-disjoint

A player appears in exactly one Next Gen discipline, so folded NGS columns are mostly NULL by design. Fold only headline metrics; keep the depth on fact_nextgen_* where the grain is honest.

Partial bridge coverage

Enrichment NULLs where no match exists are a fact of the data, not a bug. The flags keep "no match" distinguishable from "zero," and cold storage keeps the gsis-pure view recoverable.

CORE lingering

A frozen schema with no drop date becomes the stale copy someone queries by accident. Two release cycles, then drop — written into the runbook, not remembered.
