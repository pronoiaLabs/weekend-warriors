  1. dashboard
    Problem, fix, and why it waits

    Problem: every uncached dashboard query against V_PIPELINE_RUNS costs 4.6 to 6.0 seconds, and compilation (2.5 to 3.6s) exceeds execution (~2.1s). The view stack is five layers deep and Snowflake re-expands all of it per query; the result cache is disqualified by CURRENT_TIMESTAMP() and metadata table functions.

    Current mitigation: the dashboard API caches results for OPS_DASHBOARD_CACHE_SECONDS (default 60; 600 for reading sessions), so the cold path is paid once per TTL window and every other click is ~3ms.

    The fix: feed parsed logs and metric aggregates into real tables via a task on an APPEND_ONLY stream over DLT_DB.OPS.DLT_EVENTS, and point V_TASK_RUNS at those tables instead of the regex views. Cold queries should drop well under a second. Foreshadowed in the closing note of sql/ops/05_retention.sql; would also decouple parsed-log retention from raw retention.

    Why deferred: with the app cache the cold hit bites at most once per TTL window. Live with the dashboard first.

  2. dbt
    Problem and fix

    Problem: WNBA_PROD_DB.RAW.PLAYS started landing 2026-08-09 (98,658 rows on the first successful run; the provider evidently fixed the meta-less pagination that had made wnba_plays a dead pipeline since setup). Nothing models it, and the wnba_analyst agent still declines play-by-play questions with "upstream pipeline broken", which is now wrong.

    The fix: mirror NFL's play modeling shape as stg_wnba__plays → fact_wnba_play, decide whether a semantic view exposes it, and update the agent's not-available list plus the registry's stale pagination comments. Add source tests first: the table is brand new and its grain and NULL behavior are unprofiled.

  3. ci/cd
    Problem and fix

    Problem: the dbt CI job stays disabled. Its original blocker (env.yml demanded SYSADMIN) is gone: DBT_RUNNER_ROLE exists and prod envs use it. What remains is wiring.

    The fix: GRANT ROLE DBT_RUNNER_ROLE TO USER DLT_DEPLOYER;, replace the stale DBT_PROJECT_FQN / DBT_PROJECT_NAME vars (the objects are now DLT_DB.DEPLOY.CORTEX_LIFECYCLE plus per-sport _NFL / _WNBA siblings), and make the job deploy all three (a matrix or make deploy-all). The job then only needs to DEPLOY: the triggers run builds when data lands, so the CI build step becomes optional-or-removed.

  4. dashboard
    Problem and fix

    Problem: the DBT_BUILD_<SPORT> tasks are invisible to V_TASK_RUNS by design, and nothing rolls up DBT_PROJECT_EXECUTION_HISTORY, per-sport TASK_HISTORY, and the DBT_TRIGGER_LOADS audit tables into one place. The ops dashboard has no dbt panel. Also unset: retention on the audit tables (one row per load, forever; years from mattering at current volume).

    The fix: a V_DBT_RUNS view joining task history to execution history and drained loads, a dashboard card on top, and a retention task mirroring sql/ops/05_retention.sql.

  5. data
    Problem and fix

    Problem: NFL data checks that passed at authoring time now fail, and the failure set moves as the 2026 NFL season loads. Aug 8: 2 orphan team_stats rows plus two phase reconciliation failures. Aug 9: the dominant failure is source_accepted_values_nfl_raw_games_status with 149 rows (scheduled 2026 games carry new status values), and in dbt build that single source failure SKIPS 129 downstream nodes. Code unchanged; the data moved. Partly the stats?seasons[] gap, partly completed-seasons models meeting an in-progress season.

    The fix: replay affected games by game_id (the known workaround) or adjust thresholds if investigation shows benign timing. Until then NFL dbt build is red and dbt run (models only) is the clean path, which is what the NFL trigger task runs.

  6. alerting
    Problem and fix

    Problem: no alerting on Task failure (known gap). Failures are visible in the dashboard's incidents feed and V_PIPELINE_RUNS, but only if someone looks.

    The fix: a scheduled check over the same incident classes the dashboard derives (failure, record-missing, disagreement, missed slot) that posts to Slack. Two shapes: (a) Snowflake-native webhook NOTIFICATION INTEGRATION called from a Task, no container; (b) the Slack SDK in a small SPCS job with an EXTERNAL ACCESS INTEGRATION for slack.com egress. Decide dedupe/repeat policy up front so a flapping pipeline does not spam the channel; the missed-slot class needs the same young-pipeline guard as the dashboard.
