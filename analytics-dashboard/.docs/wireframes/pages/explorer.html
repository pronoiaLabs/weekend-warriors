The zero-code contract

why this page never needs a ticket

A new column added to any EXPLORE_* mart in dbt shows up here automatically — in the catalog's column list, the grid, the where-clause parser and the sort — because the page renders whatever the API describes, and the API describes whatever the table holds. The only promise a sheet makes back is row_id: stable, unique per row, safe to bookmark or join an export against. Curate columns in the mart, not in this UI.

data
contract: APP.APP_EXPLORE_* tables are the API's schema — columns[] in
          GET /api/nfl/explore is read from the table, not hardcoded
keeps:    row_id (stable key), flat single-grain rows, no nested fields
means:    add a column in dbt → it is filterable, sortable and exported here
          on the next build, with zero dashboard or API changes
